# 知源（isoLogic）产品文档

> 版本：基于当前项目代码、产品说明、PRD/SPEC 与前端页面整理

## 1. 产品概述

### 1.1 一句话介绍

知源（项目名 Logic-Coloc）是一款面向学习、研究与知识管理的跨学科学习工作台。它把“我能不能用已经掌握的知识理解一个新概念”变成可检索、可计算、可解释、可复习、可沉淀的完整流程：先理解，再发现同源关系，随后生成笔记或知识卡片，最后通过间隔复习和主动问答把知识真正掌握。

### 1.2 解决的问题

用户在学习新领域时通常会遇到四个问题：

1. 专业材料难以读懂，知道定义却不知道机制、因果关系和实际例子。
2. 不同学科之间的类比常常停留在“听起来很像”，缺少结构依据、成立条件和失效边界。
3. 搜集到的文章、帖子和资料存在重复与差异，手工整理成一篇体系化笔记成本很高。
4. 知识被读过、记过，却没有进入可持续的复习和自测流程。

知源将“理解—关联—整理—记忆—检验”串成闭环，帮助用户从一次搜索或一次阅读，走到可回看的个人知识资产。

### 1.3 产品信息架构

底部导航包含五个主模块：

| 模块 | 核心职责 |
| --- | --- |
| 求知 | 读懂专业内容，发现跨学科同源关系，进行知乎搜索与资料整合 |
| 卡片 | 用书架、书本和卡片沉淀知识，可手动新建多种类型卡片 |
| 笔记 | 结构化记录学习内容，支持排版、分类、附件和搜索 |
| 复习 | 按艾宾浩斯复习计划进行闪卡自测，查看到期任务 |
| 看山 | 查看个人学习记录、能量与等级，并进入笔记复盘 |

## 2. 功能与使用方法

### 2.1 求知：统一的知识入口

“求知”是产品的核心入口。用户可以选择“发现同源”或“读懂它”，也可以从知乎搜索进入资料研究流程。三种入口共用同一套知识理解、会话和历史记录能力。

#### 2.1.1 发现同源（核心功能）

发现同源用于回答：一个领域中的机制，是否在另一个领域中存在结构上相对应的机制？它不是简单的关键词联想，也不是让模型直接给出“像/不像”的主观结论，而是将文本理解和相似度判定拆开。

使用步骤：

1. 在“求知”中选择“发现同源”。
2. 输入或粘贴一个概念、一段专业描述，或从截图导入文字。
3. 系统先从策展知识库中检索候选概念。
4. Agent 提取输入文本的逻辑画像，并对候选进行结构比较。
5. 页面展示候选、检索分数、五维逻辑画像、同源度及原因。
6. 对达到阈值的候选，继续生成术语/机制映射、跨域学习报告、学习检查题和可靠性评审。
7. 用户可以查看“机制对照”“术语与机制角色对照”、成立条件、失效边界、已知差异和推荐学习路径，并将结果存为卡片或继续追问。

一次发现同源结果不是一个结论数字，而是一份可以继续学习的跨学科学习报告，包含：

- 原概念与候选概念的入门解释（先读懂已知领域，再认识陌生领域）。
- 共同的机制骨架与交集课程：从用户熟悉的领域逐步进入候选领域。
- 目标领域微型课程：每节包含解释、与原概念的连接、具体例子和自测题，答案可以单独展开。
- “可以带过去的直觉”与“进入第二领域必须新学”的对照，避免把类比误当成完整知识。
- 理解检查：用问题确认用户是否真正理解了映射。
- 五维结构证据：对比原概念与候选概念在五个维度上的数值和通俗原因。
- 术语与机制角色对照：展示实体、过程、信号、状态、目标、约束、失效模式等映射及证据和限制。
- 学术严谨性说明：成立条件、关键差异、失效边界和“不能这样说”的禁止外推结论。
- 来源与可核验依据：列出报告使用的来源及其支持的判断。
- 下一步怎么学：给出下一阶段的学习任务、练习或探索方向。
- 推荐书籍：根据候选领域推荐适合入门的真实书目，并说明阅读范围和理由。

系统重点比较五个逻辑维度：

- 系统封闭性：系统是否自包含、是否形成闭环。
- 因果链长度：从输入、过程到结果需要经过多少环节。
- 负反馈强度：系统的自我抑制、纠错和防失控能力。
- 随机性与熵：过程中的不确定性、噪声和随机成分。
- 资源零和性：资源是否存在竞争、守恒或此消彼长关系。

每个候选都会先展示分数，即使低于阈值也不会被静默隐藏；只有达到确定性阈值的候选才会展开映射和完整报告。报告始终强调“底层逻辑相似不等于科学等价”：类比用于迁移理解，但不替代目标学科的事实、实验和专业边界。

这是产品最重要的差异化能力：大模型负责理解、抽取和生成教学内容，Agent 负责组织任务流程，RAG 负责找候选，最终的相似度计算和阈值判断由本地确定性逻辑完成。因此结果可解释、可复核，也能明确告诉用户“像在哪里”“不像在哪里”“这个类比什么时候不能用”。

发现同源结果页本身就是一个可继续操作的学习工作区：用户可以在 Agent 对话中继续追问，并在追问过程中把阶段性理解整理进笔记，或把关键术语/机制映射添加为卡片，随后直接进入复习计划。

#### 2.1.2 读懂它

读懂它用于把用户暂时看不懂的材料转化为可学习的解释。

使用步骤：

1. 选择“读懂它”。
2. 手动输入或粘贴文字；也可以上传截图，由 OCR 自动识别文字。
3. 系统先给出一句话核心意思，再拆解关键机制、因果关系和具体例子/类比。
4. 页面同时展示该内容的逻辑画像和关键术语。
5. 对不明白的地方可以连续追问，例如“再简单一点”“为什么”“举个例子”“它和另一个概念有什么区别”。系统通过会话上下文保持前后文一致。
6. 学会专有名词后，可直接点击“存为知识卡片”，把概念和解释带入复习系统。

读懂它同样是 Agent 对话，而不是一次性摘要。用户可以在对话中逐层追问定义、原因、例子、比较和应用边界；在追问得到关键解释后，可直接保存为笔记、添加知识卡片，或者回到发现同源继续寻找跨学科连接。

读懂它适合阅读论文片段、课程材料、技术文档、截图中的定义和陌生术语。回答以用户提供的材料为依据，避免把没有证据的内容当成确定事实。

#### 2.1.3 输入方式：手动文字、截图 OCR、知乎搜索

- 手动创建：直接输入或粘贴概念、问题和段落。
- 截图识别：上传 PNG/JPG 等图片，RapidOCR 识别文字后进入读懂或发现同源流程。
- 知乎搜索：输入主题或问题，调用知乎开放平台搜索真实讨论，选择感兴趣的结果继续发现同源或进行资料整合。

### 2.2 知乎搜索与多篇资料整合

知乎搜索解决的是“资料很多，但整理很麻烦”的问题。例如用户学习 LLM 时，搜索到许多帖子都在解释同一个知识点：有的内容重复，有的角度互补，有的观点存在差异。知源可以将选中的多篇结果交给学习笔记编辑器，自动整合成一篇新的学习笔记。

使用步骤：

1. 在“求知”的导入方式中选择“知乎搜索”。
2. 输入主题或问题并搜索。
3. 浏览结果摘要，选择要作为依据的多个帖子。
4. 点击“整合为学习笔记”。
5. Agent/LLM 在限定的知乎摘要范围内去重、归纳共同知识、保留互补观点并组织出适合初学者阅读的标题和正文。
6. 生成结果会进入笔记编辑器，用户可以继续修改、选择分类、添加附件后保存。

整合不是简单拼接：系统会尽量合并重复知识、区分不同解释角度，并将多条材料组织为一篇有结构的学习笔记。生成内容的事实边界受所选摘要约束，不应把摘要之外的内容当作来源事实。

在支持知乎授权的部署中，用户还可以连接自己的知乎账号，整理个人收藏和点赞内容，并在“知乎知识库”入口中查看同步结果或相似内容。授权按用户隔离，个人收藏不会与其他用户共享。

### 2.3 卡片：把知识变成可复习单元

卡片不是只能从“读懂它”生成。用户可以在“卡片”栏目直接新建，也可以把发现同源报告、读懂它解释或知乎整合笔记中的内容保存为卡片。

卡片采用“正面概念 / 背面解释”的结构，支持正反面插图，并按“书架 → 书本 → 卡片”组织。适用类型包括：

- 数学公式：正面写公式或条件，背面写含义、推导或使用场景。
- 专有名词解释：正面写术语，背面写定义、机制和例子。
- 英文单词：正面写单词，背面写词义、例句和易错点。
- 跨学科映射：正面写来源概念，背面写候选领域中的对应机制和边界。
- 任意自定义知识点：用户可以自由填写正面和背面。

卡片支持新建、编辑、删除、移动书本、查看掌握状态和批量管理。卡片还可以从“求知”结果一键进入复习计划，形成从理解到记忆的直接通路。

### 2.4 复习：基于艾宾浩斯曲线的主动回忆

复习栏目按照艾宾浩斯记忆曲线安排复习节点，页面提供复习计划和曲线可视化。产品重点使用第 1、2、4、7、15 天的间隔提醒：新卡片建立后，系统会把它排入这些日期对应的计划，告诉用户今天该复习哪些知识卡。早期节点还会覆盖 5 分钟、30 分钟和 12 小时，用于刚学完后的快速巩固。

这种排期特别适合碎片化时间：吃饭、通勤、排队或课间打开“复习”，用几分钟完成几张闪卡；系统会把需要复习的内容自动带到当天，不需要用户自己记住“哪张卡什么时候该看”。如果错过某个节点，计划页会保留“已逾期”状态，用户可以继续补做。

一次闪卡复习包含三步：

1. 先看正面，在答案揭示前选择“认识 / 模糊 / 忘记了”。
2. 翻面查看背面解释。
3. 再次确认“下一词”或“记错了”，允许用户推翻第一次自评。

只有“认识”并在翻面后确认“下一词”，才会被判定为本轮掌握并进入下一阶段；模糊、忘记或翻面后改口的卡片会回到本轮队尾再次出现。这样可以减少“看见答案后误以为自己会了”的假性掌握。

复习结束后会显示复习数量、掌握数量、模糊/遗忘数量，并根据学习行为增加能量。已掌握卡片、未掌握卡片和全部卡片可以分别筛选，也可以重置状态、批量删除或移出已掌握列表。卡片的下一次复习时间、复习阶段和最近复习时间会持续更新，因此“今日复习”与“复习计划”既能看当前待办，也能看完整的 1/2/4/7/15 天时间表。

### 2.5 笔记：结构化知识资产

笔记栏目用于长期保存学习成果。笔记以 Markdown 风格的结构化内容组织，界面提供可视化排版工具，支持标题层级、粗体、斜体、下划线、文字颜色、背景高亮、有序/无序列表和图片插入，让笔记清晰、易读、便于复盘。

主要能力包括：

- 新建、编辑、重命名、删除笔记。
- 新建文件夹/分类，移动笔记，删除文件夹后自动将内部笔记移回根目录。
- 笔记搜索。
- 列表视图与网格视图切换。
- 收藏标记和批量管理，支持全选、分享、导出、移动和删除等操作入口。
- 新建时选择封面、纸张样式（空白、宽横格、窄横格、点阵、小格纹、中格纹）和纸张颜色（白、米黄、黑），也可以上传自定义封面。
- 添加图片和 PDF 附件，支持附件预览。
- 在正文中插入图片；附件和正文一起作为后续笔记复盘的材料。

笔记不仅是最终输出，也是系统内部的知识中间层：知乎多篇整合结果可以保存为笔记，笔记又可以被“看山—笔记复盘”读取和提问。

### 2.6 看山：笔记复盘（重点功能）

笔记复盘是知源把“保存过的知识”重新变成“能够说出来、答出来”的主动学习功能，也是“看山”模块的核心亮点。它不是让用户重新阅读笔记，而是由 Agent 作为复盘导师，阅读用户的笔记材料，动态提出问题、等待回答，再根据对话继续追问。

#### 使用流程

1. 进入“看山”，打开“笔记复盘”。
2. 在笔记列表中搜索标题或正文，选择要复习的笔记。
3. 确认开始后，Agent 先读取笔记正文；如果笔记包含 PDF 或图片附件，系统会同步提取 PDF 文字层或调用 OCR 读取图片文字。
4. Agent 从第一道问题开始，一次只提出一个考察问题，用户在对话框中作答。
5. 用户回答后，Agent 可以继续追问定义、原理、因果链、应用场景、反例、边界和设计取舍，形成多轮主动回忆。
6. 结束复盘后，系统保存完整对话，并生成一份复盘小结：覆盖了哪些内容、哪些回答准确、哪些概念薄弱、下一步应该再看什么。
7. 在“历史记录”中可以按笔记回看复盘对话和小结，也可以删除记录。

#### 为什么它是亮点

- **真正基于个人材料出题**：问题来自用户自己的笔记，而不是通用题库；笔记写得越完整，复盘越贴合个人学习目标。
- **Agent 驱动的动态追问**：不是固定顺序的静态问答。Agent 会根据上一轮回答决定下一问，既可以从基础定义开始，也可以逐步加深到机制、比较、应用和边界。
- **正文与附件一体化**：课程 PDF、论文、截图和图片资料可以作为笔记附件，复盘时和正文一起作为出题依据；无法读取的扫描件会明确提示，不会伪造理解。
- **适合多种场景**：可以模拟技术面试、产品面试、论文答辩、口试、期末考试，也可以把一篇读书笔记变成自测题库。
- **复盘结果可回看**：每轮对话和自动小结都会保存，用户可以比较自己不同时间的回答，定位长期薄弱点。

#### 典型使用方式

- **模拟面试**：对项目笔记连续追问“为什么这么设计”“如果流量翻倍怎么办”“这个方案的失败边界是什么”。
- **期末复习**：选中一章课程笔记，让 Agent 逐题考察概念、公式、推导和综合应用，形成个人题库。
- **论文/读书复盘**：检查能否说清论点、证据、方法、结论和局限，而不只是重新浏览页面。
- **技术知识巩固**：把 LLM、RAG、数据库或系统设计笔记交给 Agent，进行由浅入深的口头问答。

### 2.7 看山：成长体系

“看山”同时承担个人学习主页和成长反馈功能。笔记复盘、卡片复习、发现同源、读懂新概念等行为都会沉淀为学习记录与能量。

#### 学习成长

系统根据学习行为累计能量，例如每日登录、读懂新概念、连续追问、发现同源、保存卡片、复习掌握、新建笔记和整理书架。能量对应五级称号：

| 等级 | 称号 | 能量区间 |
| --- | --- | ---: |
| LV.1 | 学术萌新 | 0–99 |
| LV.2 | 知识学徒 | 100–299 |
| LV.3 | 科研助手 | 300–499 |
| LV.4 | 探索达人 | 500–999 |
| LV.5 | 刘看山首席研究员 | 1000+ |

页面还展示已掌握卡片、未掌握卡片、笔记数量和学习天数，并提供等级规则与积分明细。

### 2.8 历史、账号与数据隔离

求知历史按“跨学科理解、读懂它、知乎研究”分类保存，可恢复历史输入和部分完整结果。应用首次访问会自动创建游客身份，用户无需先填写注册表单即可使用；服务端数据按用户 ID 隔离保存。头像、昵称、签名、笔记、卡片、复习进度、能量和复盘记录都属于个人数据。

## 3. 技术栈与系统实现

### 3.1 总体架构

系统采用“单页 H5 前端 + FastAPI 后端 + LangGraph Agent + 本地 RAG/逻辑引擎 + 外部大模型”的分层结构。

```text
浏览器 H5（HTML/CSS/原生 JavaScript）
        │ REST API
FastAPI 路由与 Service 层
        ├── LangGraph Agent 工作流
        │     ├── 意图路由
        │     ├── 文本特征抽取
        │     ├── RAG 候选检索
        │     ├── 同源度计算/映射/批判
        │     └── 会话记忆与复盘对话
        ├── 确定性逻辑引擎（五维画像、余弦/Wasserstein）
        ├── OCR 与附件文本抽取
        └── 按用户隔离的 JSON 文件存储
```

### 3.2 前端技术

- HTML5：页面结构、底部导航、弹层、全屏页和表单。
- CSS3：响应式 H5 布局、卡片化界面、复习计划曲线、模板纸张样式和移动端性能模式。
- 原生 JavaScript：状态管理、页面切换、API 调用、富文本编辑、历史恢复、批量操作、卡片复习和复盘聊天。
- 不依赖 React/Vue 等前端框架，静态资源由 FastAPI 托管。

笔记编辑器使用 `contenteditable` 与浏览器编辑命令实现排版，正文以结构化 HTML 保存并在界面上呈现 Markdown 风格的层级化阅读体验；图片可以插入正文或作为附件保存。

### 3.3 后端与 API

- Python 3.13。
- FastAPI 0.138：REST API、上传、鉴权依赖和静态文件服务。
- Uvicorn：应用服务器。
- Pydantic 2：请求/响应模型和 Agent 数据契约，限制结构化 JSON 输出。
- Service 层统一连接会话、RAG、Agent、OCR 和持久化模块。

主要接口能力包括：

- `/api/explain`：读懂它的解释。
- `/api/chat`：连续追问与笔记复盘对话。
- `/api/discover`、`/api/discover/{request_id}`：异步发现同源、查询状态和取消任务。
- `/api/ocr`：截图文字识别。
- `/api/zhihu/search`、`/api/zhihu/research`：知乎搜索与多资料整合。
- `/api/notes/*`、`/api/library`：笔记、文件夹和书架数据。
- `/api/cards/*`：卡片保存、到期查询、复习排期和复习结果。
- `/api/reviews/*`：笔记复盘记录、详情、小结和删除。

发现同源是长任务，后端使用后台线程、任务状态查询、超时和取消机制，避免网关因为单次推理时间较长而直接断开。

### 3.4 Agent 与 LangGraph

系统使用 LangGraph 编排一个可追踪的知识 Agent。典型流程如下：

1. `load_context`：加载当前会话的稳定知识上下文、摘要和最近消息。
2. `route_intent`：根据显式模式和用户输入识别读懂、追问、举例、比较或发现同源等意图。
3. `extract_features`：调用特征抽取工具，把文本转成逻辑画像和关键术语。
4. `retrieve_candidates`：在 RAG 语料中检索候选概念。
5. `calculate_homonomy`：对候选计算确定性同源度，低于阈值的候选不生成映射报告。
6. `generate_response`：生成解释、学习报告、映射、推荐学习路径和可靠性信息。
7. `save_conversation`：保存会话消息，支持连续追问和复盘历史。

Agent 工具层还包含实体映射、学习报告、报告批判、复盘小结等结构化工具。报告要求明确来源、证据、成立条件、失效边界、已知差异和禁止外推的结论。

笔记复盘使用同一套 Agent 会话能力，但会把选定笔记正文和附件抽取文本加入知识上下文，并要求每次只提出一个问题，便于用户逐题回答。

### 3.5 RAG：候选发现与证据约束

RAG 当前采用随包分发的本地策展语料库（`data/corpus`）和确定性 Retriever：

- 语料以候选概念、描述、机制、关键术语、来源和逻辑画像组成。
- Retriever 根据文本关键词、关键术语和逻辑特征进行加权检索。
- 检索结果带有 `retrieval_score` 和检索理由。
- RAG 负责“找哪些候选值得比较”，不直接决定“是否同源”。

这种分离避免把检索相关性误当作同源结论，也让候选来源和报告证据可追踪。候选的同源判断由逻辑引擎独立完成。

### 3.6 确定性逻辑画像与同源度

特征抽取器让大模型把自然语言材料转换为固定 JSON 结构的五维向量，每个维度为 0–100。随后由本地逻辑引擎计算两段文本的同源度，默认使用余弦相似度，也支持 Wasserstein 作为方法配置。

默认同源阈值为 0.72。大模型不能修改或重算这个分数；它只能依据已经计算出的分数和候选材料生成教学报告与批判说明。这样可以保证同样输入在判定层面可复现，并能解释每个维度对结果的贡献。

### 3.7 大模型连接与结构化输出

项目通过 `LC_BRIDGE`、`LC_API_KEY`、`LC_MODEL` 等环境变量连接 OpenAI-compatible 或 Anthropic-compatible 的模型端点。模型主要承担：

- 解释、简化、举例、比较和追问。
- 从文本抽取关键术语与五维逻辑特征。
- 生成跨学科学习报告、实体映射和推荐学习路径。
- 整合知乎摘要为学习笔记。
- 根据笔记复盘对话生成复盘小结。

Pydantic Schema 对解释响应、发现报告、映射证据、批判结果、卡片、笔记和复盘记录进行约束；报告输出要求严格 JSON，复盘小结使用受长度约束的中文正文。

### 3.8 OCR、PDF 与附件处理

- `rapidocr_onnxruntime`：截图和图片附件 OCR。
- `pypdf`：提取 PDF 文字层并保留页码标记。
- 附件读取有大小、数量和总字符预算；过长内容按开头节选交给 Agent。
- 附件抽取结果带内存缓存，避免同一附件重复解析。
- 扫描件无文字层时返回可见降级提示，不将空内容伪装成已读取。

### 3.9 数据存储与会话

项目使用轻量文件存储，按用户目录隔离：

- `data/users/<uid>/`：笔记、卡片、书架/分类、复盘记录、知乎资料和用户信息。
- `uploads/<uid>/`：图片、PDF、头像和笔记附件。
- 文件写入使用锁、临时文件和原子替换，降低并发写入造成 JSON 损坏的风险。
- LangGraph 会话上下文保存在进程内存，用于连续追问；复盘完整记录会另行落盘，便于服务重启后回看。
- 前端保留本地缓存作为断线或后端暂不可用时的降级体验，成功连接后再同步云端。

当前产品采用点击即用的游客身份；前端不展示注册/登录流程，但后端保留账号升级、注册和登录接口作为备用能力。公开部署时需要固定实例数和持久化卷，否则内存会话或用户文件可能丢失。

### 3.10 部署与运行

- Dockerfile 基于 `python:3.13-slim`。
- 通过 Uvicorn 启动 FastAPI 应用，浏览器访问根路径即可使用 H5。
- 可部署到 CloudBase 等容器托管环境。
- 线上需要配置模型密钥、固定 `LC_SECRET_KEY`、将 `data` 和 `uploads` 挂载持久化卷，并保证请求超时大于发现同源任务时长。
- 项目提供离线 CLI 演示、单元测试和容器冒烟测试；离线演示使用预置文本与缓存，不代表 Web 端的实时模型调用。

## 4. 产品闭环总结

知源不是把几个 AI 小工具简单并排，而是一条连续的学习链路：

```text
输入文字 / 截图 OCR / 知乎搜索
        ↓
读懂它 或 发现同源（Agent + RAG + 确定性逻辑判定）
        ↓
保存为卡片 / 整合为学习笔记
        ↓
艾宾浩斯闪卡复习
        ↓
看山查看成长记录，或对笔记进行 Agent 复盘
        ↓
继续追问、补充笔记、再次复习
```

其中，“发现同源”负责把熟悉领域与未知领域连接起来；“知乎整合”负责把分散资料变成可读笔记；“卡片与复习”负责把理解变成长期记忆；“笔记复盘”负责检验是否真的能说出来、答出来。最终形成从探索、理解到掌握和再验证的完整个人知识系统。
